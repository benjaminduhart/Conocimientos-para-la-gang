# 🧠 Conocimientos para la Gang — Second Brain Industrial

> **Un cerebro digital compartido entre amigos.** Desde el cableado del cuadro hasta el código del PLC, desde la mecánica hasta la nube: unimos mantenimiento electrónico industrial, automatización, ingeniería (electrónica, mecánica, telecomunicaciones e informática) en un solo lugar, bien organizado y pensado para crecer con el tiempo.

---

## 🎯 ¿Qué es este espacio?

Este es nuestro **second brain** colectivo, inspirado en la idea de Andrej Karpathy de externalizar el conocimiento para pensar mejor y recordar menos. Aquí guardamos lo que aprendemos, resolvemos y reutilizamos entre colegas: no queda en cabezas sueltas ni en chatGroups olvidados.

La meta es simple: que cualquiera de la gang pueda entrar, encontrar rápido lo que necesita y aportar lo suyo sin fricción.

---

## 🌐 Áreas de conocimiento

- **Mantenimiento electrónico industrial** → reparaciones, diagnóstico, instrumentación, drives.
- **Automatización** → PLC, HMI, SCADA, sensores, actuadores, redes industriales.
- **Ingeniería electrónica** → diseño, PCB, fuentes, electrónica de potencia.
- **Ingeniería mecánica** → CAD, mantenimiento mecánico, neumática, hidráulica.
- **Telecomunicaciones** → redes, cableado estructurado, comunicaciones, radio/fibra.
- **Informática** → sistemas, scripting, bases de datos, software de soporte.

## 📂 Organización: de lo general a lo concreto

Seguimos una estructura en capas, recomendada por quienes usan Obsidian y gestión de conocimiento a largo plazo:

| Nivel | Tipo | Ejemplo |
|-------|------|---------|
| **1. Índices y mapas** | Notas de navegación | `Mapa de Navegación (General)` |
| **2. Áreas grandes** | Carpetas temáticas | `automacion`, `electronica`, `mecanica`, `telecom`, `computing` |
| **3. Subtópicos** | Subcarpetas | `computing/py`, `automacion/plc`, `electronica/fuentes` |
| **4. Notas atómicas** | Archivos concretos | `py_dict.md`, `plc_siemens_tia.md`, `fuente_switching.md` |

**Reglas de oro:**

- De lo general a lo específico: primero el mapa, luego la carpeta, luego la nota exacta.
- Cada nota va en la carpeta que le corresponde; si no existe, se crea con sentido común.
- Usamos `tags` (#python, #plc, #mantenimiento, #electronica) para cruzar ideas entre carpetas.
- Enlazamos notas con `[[Nombre de la Nota]]` para que todo quede conectado en red.

## 🚀 Guía para principiantes

### 1. ¿Dónde estoy parado?

Empieza por:

1. **`[[Bienvenido]]`** — entiende el espíritu del vault.
2. **`[[Mapa de Navegación (General)]]`** — tu brújula para moverte.
3. **`[[Reglas de Colaboración Horizontal]]`** — cómo aportamos sin romper nada.

### 2. ¿Cómo aportar?

No hace falta ser experto. Si aprendiste algo, apúntalo:

- **Crea una nota** con un nombre claro y breve.
- **Ponle el encabezado adecuado**: título, contexto, y si aplica, un ejemplo práctico.
- **Usa tags** al final o en el YAML frontmatter: `#plc`, `#python`, `#mantenimiento`, etc.
- **Enlaza con otras notas** usando `[[...]]` para conectar ideas.
- **Si mejores algo ajeno**, edítalo y deja una línea de changelog o tu firma con fecha.

### 3. Mini-formato recomendado para notas

```markdown
# Título claro

Contexto: ¿qué problema resuelve esto?

## Cuerpo
- Paso 1
- Paso 2
- Ejemplo de código/esquema/dato

## Tags
#area #subtema #nivel

## Relacionado
[[Otra nota útil]]
```

### 4. Consejos para no perderse

- **Busca primero** para no duplicar. Ctrl + Shift + F en Obsidian.
- **Prefiere notas cortas** y concretas antes que una gigante.
- **Prefiere un mal aporte hecho hoy** a un aporte perfecto que nunca llega.
- **Pregunta en el grupo** si no sabes dónde poner algo; entre todos decidimos.

## 🤝 Filosofía de colaboración

- **No hay jerarquías de conocimiento.** Un tip de mantenimiento vale tanto como un script de Python.
- **Construimos en red.** Cuanto más conectemos notas, más útil se vuelve el cerebro.
- **El vault vive.** No buscamos perfección inmediata; buscamos mejorar poco a poco.
